XGC OPERATOR SKINS MODE — 45 OWNER-SUPPLIED UNLOCKS

This is an additive update for the existing build 3/build 4 tracker. It does not replace your current guides, artwork, or application logic.

RECOMMENDED INSTALL: EMBED INTO YOUR EXISTING INDEX.HTML
1. Extract add_operator_skins.py and operator-skins.js into the folder containing your current index.html.
2. Run: python add_operator_skins.py
3. The installer updates that index.html and keeps index.before-skins.html as a backup.
4. Upload ONLY the updated index.html to your repository and wait for deployment. Hard refresh afterward.

The installer embeds all operator code/data in index.html. You do not need to upload operator-skins.js or the Python installer for the embedded version. Keep your existing assets and .nojekyll. Do not upload your backup unless you want it public.

ALTERNATIVE: SCRIPT INCLUDE
Upload operator-skins.js beside index.html, then insert this immediately before </body>, AFTER the existing application scripts:
<script src="./operator-skins.js?v=1" defer></script>
Use either this method OR the embed installer, not both.

FEATURES
Third Operator Skins mode; 45 entries (44 skins plus The Warden operator); independent session-only progress; operator and category filters; remaining-only; separate reset; expandable requirements. Requirements come from the user's supplied checklist, not an external verification pass. The Warden is explicitly an operator unlock. No skin artwork filenames have been assumed or added. No game/account integration or permanent saving.

PACKAGE CONTENTS
operator-skins.js — add-on code and data
add_operator_skins.py — embeds the add-on into YOUR existing complete application
operator-unlocks.json — editable reference data (not loaded at runtime)
TEST-RESULTS.txt — browser and installer checks

The package intentionally does not include a replacement index.html: the installer preserves your exact current application instead of recreating or downgrading it. Browser tests used representative tracker markup and event handling, not the live deployed page.
